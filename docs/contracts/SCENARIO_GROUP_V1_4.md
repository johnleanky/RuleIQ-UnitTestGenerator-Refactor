## Resolution and ownership

For each access, Author resolves declared Data Page inputs against the caller state immediately before the access: explicit expression first; otherwise a present same-name current Param value under the user-confirmed RuleIQ convention; otherwise an evidenced applicable runtime default. Presence includes null and initialized empty. Unresolved explicit/current values do not fall through. Unknown declarations are not empty declarations. Optional omitted inputs require declaration evidence that omission is permitted; otherwise missing values are unresolved.

During crawl, record symbolic expressions and their producers without requiring future concrete scenario values. During execution, evaluate reachable accesses in order, retain skipped-access evidence, and freeze typed values and signatures. Only external inputs are seeded. Parameter resolution refines testability without adding dependency-only scenarios or removing existing scenarios. The broader scenario lifecycle remains a separate correction.

KnowledgeTool supplies Data Page semantics to Author; Generator audits frozen records, never infers bindings. Validator continues candidate-visible checks only. Data-Page-to-loader pass-current-page settings do not establish caller-to-Data-Page bindings. Existing Thread-only eligibility remains in force.

## Evidence format

Use existing scenario-scoped EVIDENCE records; `fact` contains canonical minified typed JSON, with ordinary outer ledger escaping. These are normalized evidence formats, NOT invented Pega RuleJSON fields. Original metadata/expression excerpts remain separately referenced EVIDENCE. Unknown export mappings yield unknown declarations.

- `kind=DEPENDENCY`, `source=DP_DECLARATION/<rule>`: exact fact keys `rule`, `scope`, `parameters`, `optional`, `defaults`, `evidence`. `parameters` is a sorted unique input-name array, or null when unknown; `optional` is a sorted unique subset; `defaults` maps declared input names to typed carriers; `evidence` is a nonempty unique list of other metadata EVIDENCE IDs. Each default is included only with evidence of runtime applicability. Unknown declarations have empty optional/default sets. Scope comes from evidenced metadata.
- Typed carrier: exact keys `valueType`, `value`. Types and string value carriers follow PARAM: null is `{"valueType":"null","value":"null"}`, initialized empty is `{"valueType":"empty","value":"<EMPTY>"}`, and absent is `{"valueType":"absent","value":null}`. Only absent uses JSON null for its carrier.
- `kind=EXECUTION`, `source=DP_ACCESS/<invocation>`: exact fact keys `rule`, `invocation`, `execution`, `declaration`, `status`, `explicit`, `current`, `parameters`, `simulation`. `execution` references the access RX; its source equals invocation. `status` is EXECUTED, NOT_EXECUTED or UNKNOWN. `declaration` references matching DP_DECLARATION evidence. `explicit` maps supplied declared names to typed carriers plus `expression` and nonempty `evidence` IDs. For executed accesses with known declarations, `current` has exactly every declared input name; each entry has a typed carrier, nonempty `evidence` IDs and `state=ABSENT|VALUE|UNKNOWN`. ABSENT and UNKNOWN use the absent carrier; VALUE uses a non-absent carrier. `parameters` is the sorted unique list of this access's PARAM IDs; `simulation` is its SIM ID or null. Skipped/unknown accesses have empty explicit/current/parameters and null simulation. Unknown accesses require GAP DP_ACCESS_UNRESOLVED, scope=invocation, citing access evidence; they downgrade testability. Executed accesses with unknown declarations have empty current/parameters and null simulation and require DP_PARAMETER_UNRESOLVED.
- `kind=EXECUTION`, `source=DP_EXECUTION/<RXid>` has exact fact keys `execution`, `status`, referring to that RX and the same three execution states. Require exactly one for every access RX and every relevant Param producer RX. Access status must match. A false RX guard requires NOT_EXECUTED, an unknown guard requires UNKNOWN; an executed producer requires a true or absent guard. Relevant PRODUCER guards equal their RX guards, and their payloads use the typed carrier shape above. Every RX whose comma-separated writes includes a relevant Param.<name> has exactly one matching PRODUCER for that target. Every relevant PRODUCER references an RX listing its target. Duplicate producers for one RX/target are invalid.
- Require one initial EVIDENCE per declared name used by an executed access: `kind=SEED`, `source=DP_INITIAL/Param.<name>`, fact equal to its typed carrier. Absent means evidenced initial nonexistence, not unknown state. For each access, derive current state from this initial fact and all relevant producers with lower RX.order. NOT_EXECUTED preserves state; UNKNOWN makes it UNKNOWN; EXECUTED replaces it with the producer carrier (absent means removal). Compare the complete current snapshot against this derived state. Its evidence must include the initial fact when it remains the origin, otherwise the final relevant producer's evidence and DP_EXECUTION fact. Missing names, unproven absence and stale values fail validation. Current UNKNOWN never permits fallback; current ABSENT permits an evidenced default or optional omission. These snapshots validate Author-acquired facts, not re-execution of Pega.

## PARAM and SIM rules

Execution-state proof is bidirectional: NOT_EXECUTED requires a terminal false effective RX guard (including the parent/short-circuit guard where applicable); a true or absent guard cannot justify skipping a producer. Without sufficient execution proof retain UNKNOWN. A false guard requires NOT_EXECUTED and an unknown guard requires UNKNOWN. The final relevant producer used as current-state origin means the last state-affecting producer, excluding NOT_EXECUTED producers.

Add PARAM `mode=default`, with absent expression and inheritance=n_a. DP explicit uses inheritance=n_a; inherited uses inheritance=enabled and expression=Param.<name>. Every resolved parameter is bound to its access invocation and Data Page rule, and cites the access plus declaration evidence. Non-formal DP PARAM records retain absent formalType/formalEvidence.

Every resolved executed eligible access references one SIM with matching rule and typed effective map. Every SIM is associated with at least one access and links those access/declaration evidence IDs. Accesses with the same rule/signature/map may share a SIM; distinct maps cannot share a signature. SIM.parameterResolutions selects one complete access's parameter list (not duplicate names accumulated from repeated accesses). All accesses retain their own PARAM rows. Comparison preserves JSON types, including Boolean versus number.

`params={}` and `parameterResolutions=-` are valid only for an evidenced empty effective map. Nonempty maps have one PARAM per name, with no missing, extra, duplicate or unrelated references. All actual SIMs require Thread scope. Unresolved or excluded-scope executed accesses have no SIM and retain a matching GAP with code DP_PARAMETER_UNRESOLVED or DP_SCOPE_INELIGIBLE, scope equal to invocation, and access evidence; scenario testability reflects the gap. No guessed bindings or dummy PARAM rows.

## Validation boundary

The static checker verifies normalized declaration/access evidence and execution provenance against frozen RX/PRODUCER/PARAM/SIM records. It does not invent raw Pega metadata field mappings, discover unrecorded arbitrary RUT accesses, or evaluate arbitrary expressions. Labeled GetCaseData fixture expectations and connected source-to-candidate tests are separate evidence categories.

## Crawler controls

`CRAWL|ruleCrawlerCalls=<N>|dependencyReferencesRequested=<N>|triggeredLimits=<codesOrAbsent>`

Both counters are nonnegative integers, bounded by 120 calls and 260 requested references. Triggered limits are the sorted complete set: RULECRAWLER_CALL_CAP exactly at 120, RULES_TOTAL_REQUESTED_CAP exactly at 260; otherwise absent. Each Scenario's EXECUTION_AUDIT wave census matches ruleCrawlerCalls and the sum of wave plan.OUT lengths matches dependencyReferencesRequested, counting repeat requests on different calls. Preserve wave state, closure and terminal-gap checks. No further crawl may exceed a budget. No scores, tiers, metric thresholds or computed confidence/testability caps are emitted or projected. Confidence/testability follows executable inputs, actual evidence, unresolved dependencies, supported assertions and explicit omissions; removing a cap does not promote a Scenario automatically.

The current PROFILE checklist has 16 Author-owned booleans, excluding ComplexityComputed. The Generator projects those facts and owns its existing two local gates. Validator checks candidate-visible facts only and never reconstructs implicit bindings. Historical source validation remains explicitly revision-scoped; current consumers accept only 1.4.
