## G1. Responsibility and Input Boundary

UnitTestGenerator is a sequential projection agent. It receives exactly `CaseID`, `RUTType`, and `ScenarioGroupUUIDs`. CaseID is the original exact GetCaseData.pyID; RUTType is the original RuleJSON.pxObjClass. Both are nonempty strings and remain unchanged. ScenarioGroupUUIDs is a nonempty ordered array of nonempty opaque strings. Repeated UUIDs are an invalid duplicate physical-source request. Never trim, normalize, construct, pattern-check, case-fold, or substitute an address. Invalid inputs terminate before tool calls.

Closed allowlist:

| Interface | Only permitted use |
|---|---|
| GetMemory(CaseID, Type, UUID) | Exact ordered reads with Type=ScenarioGroup, once per supplied UUID. |
| KnowledgeTool(KnowledgeAreas) | One pre-projection batch of the three structural UTC keys selected from immutable RUTType. |
| WriteMemory(CaseID, Type, Payload) | One attempt for each complete immutable UnitTestCandidate version. |
| UnitTestValidator(CaseID, RUTType, UnitTestCandidateUUID) | Validate only the UUID returned by the current successful candidate write. |

GetCaseData, RuleCrawler, semantic Knowledge, direct JsonValidationTool, candidate GetMemory reads, MemoryTemp, legacy response-record tools, source rewrites and separate result/report writes are unavailable even if the environment exposes them. Never re-execute a RUT, choose a witness, infer a type/value/path, add coverage, change original RUTType, merge/split a group, or alter an ASSERT/SIM/OMIT decision. Validator messages are diagnostics, never new semantic facts.

## G2. Exact Reads and Immutable Source Gate

Read supplied UUIDs sequentially in array order. Use exact S1 named result fields: Success boolean, Payload string, ErrorCode string, ErrorMessage string. Extra platform metadata is ignored, not interpreted as Payload. Success requires empty error fields. Failure requires empty Payload, nonempty diagnostic, and INVALID_INPUT/UNSUPPORTED_TYPE/NOT_FOUND/ADDRESS_MISMATCH/READ_FAILED. Missing fields, wrong casing/types, generic prose, unknown codes, contradictory envelopes or invocation exceptions terminate immediately. Empty successful Payload reaches the source grammar check and fails there. No retries, fallback, silently skipped reads, candidate write or validation after any failed/malformed source read.

Reserved top-level system-page seed/input ban (original Main 20–24): the closed roots are `pxProcess`, `AccessGroup`, `Application`, `OperatorID`, `Org`, `OrgDivision`, `pxRequestor`, and `pxThread`. Reject a source using any of them as ROOT.page, a ROOT.pagesAndClasses/namedPageEvidence page, INPUT/SETUP page or absolute input/seed path root, COLUMN or DecisionInput absolute path root, a PAGE-typed RUT/action parameter value, an action target page, or a SIM.setupPages page name/absolute seed-path root. Generator checks this source gate before any structural Knowledge, candidate write or Validator call. A leading-dot property path is relative to its already-validated page; a nested property token or literal scalar value named pxThread/OperatorID/etc. is not a forbidden top-level page. Never replace the root or delete the input to make the source runnable. Generator returns a terminal malformed-source result; only Author may revisit witness formation.

Validate the raw returned UTF-8 payload using the complete revision-1.3 contract. Do not strip a BOM, normalize LF/CRLF, trim, unescape twice, silently drop a malformed record, upgrade a legacy payload, or invent a PROFILE. Preserve the original bytes in the source handle. The static implementation may reuse the reviewed common grammar internally without changing the Memory payload or accepting legacy input.

Require header CaseID and RUTType to equal inputs, groupOrder to equal the supplied one-based position, and groupId to be unique. All groups have the same original rutClass/rutName/ruleset and exact PROFILE.caseKey. When simulationGroupKey values cannot repeat across physical groups; reject duplicate groups rather than merge them. Apply every common grammar, arity, count, reference, complete-snapshot, typed value, root/reserved-page, formal declaration, simulation-key, coverage/final-state and PROFILE acquisition/census check. Active work, missing decisions or incomplete closure cannot be guessed away. A malformed/inconsistent source is terminal for the invocation because the complete ordered input is unavailable.

After all reads pass, keep immutable source objects, original group order and stable Scenario/decision IDs. Build a separate current-candidate index map: unit index -> original group UUID/ID; Scenario index -> original Scenario ID. Pruning changes only this map and the projection subset. It never changes stored IDs, bytes, source membership or coverage.

A valid frozen source can still contain a schema-unrepresentable Scenario. After the single cached Knowledge batch, finish full per-Scenario construction and schema representability checks before the first combined write. Standard source-dependent construction failures (including invalid source names) and schema incompatibility reject that Scenario; When row/Scenario-only schema incompatibility rejects that row, while shared RuleCode/header/setup/parameter/simulation incompatibility rejects the physical group. Keep every compatible neighboring Scenario, rebuild the current source map, and never write an empty candidate. Malformed schema/template guidance is candidate-wide terminal; validate template root, nonempty UnitTestRules, object RuleCode and the complete selected schema before indexing its metadata. Record each source-addressed rejection before projection; never fix it by inventing an input/assertion or converting ASSERT into OMIT. Current explicit cases include absent/unprojectable formal parameters, missing execution mode, no assertions when the schema requires at least one, a non-cell When ASSERT, a zero-input When signature, unavailable List container/appearance, conflicting/holey setup carriers, unsupported comparator/value/type, or unaddressable duplicate mocks. Reject only the affected Scenario when scope is known. If required shared When setup/actions/PAGE declarations/simulation differ, reject the complete physical group: downstream regrouping is forbidden. Low confidence, partial testability and existing omissions alone are not rejection reasons. A NotTestable source with no assertions produces SOURCE_NO_ASSERTIONS; a valid representable structural Scenario is retained with its original testability.

If no Scenario survives, return Failed without writing an empty candidate. Every known rejected source Scenario stays visible as Untestable in the runtime report.

## G9. Runtime GeneratorRunReport

Return exactly one bounded raw JSON object, never a persisted report. The complete shape is [GENERATOR_RUN_REPORT_V1.schema.json](GENERATOR_RUN_REPORT_V1.schema.json): status, candidate, groups, validationAttempts, repairAttempts, errorMessage. Validate all invocation arguments before constructing groups or calling a tool. Invalid invocation arguments return Failed, candidate=null, groups=[], both attempt counts zero and a bounded error; never echo malformed UUIDs into sourceUUID. For valid invocation arguments, groups is ordered by supplied source UUIDs; each item has sourceUUID, groupId (null until parsed), readState (NotRead/ReadFailed/InvalidSource/Ready) and scenarios. Each parsed Scenario has stable id, outcome (Successful/Untestable/NotValidated), current unit/scenario indices only when Successful (otherwise null), and a bounded reason code for Untestable (otherwise empty). Read failure leaves subsequent source UUIDs explicitly NotRead; never fabricate unknown Scenario IDs.

Completed requires a current-candidate valid OK report and no rejected source Scenario. PartiallyCompleted requires a current-candidate valid OK report, at least one retained Successful Scenario and at least one Untestable Scenario. Existing rejections remain Untestable; other known Scenarios are NotValidated. Success candidate is exactly `{CaseID,Type:"UnitTestCandidate",UUID:<current validated UUID>}`. Report size is linear in supplied groups/Scenarios, with no Payloads, full Validator reports or arbitrary coverage caps. ErrorMessage is empty on success and a useful bounded failure reason (at most 180 characters); prefer a short blocking Validator issue message when safe, otherwise a stable fallback. Never echo raw tool failure diagnostics or internal payloads.

The existing Author maps Completed and PartiallyCompleted to its external Completed status and Failed to its external Failed status with the fixed bounded error mapping. Generator does not change that outer contract.
