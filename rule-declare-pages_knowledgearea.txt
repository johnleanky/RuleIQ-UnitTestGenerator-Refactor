KDP.1|F|CoreFields
P: Rule type, key, and identity fields for Rule-Declare-Pages.
M: pxRuleObjClass="Rule-Declare-Pages"; pyRuleName=Data Page name (e.g. D_CustomerList);
   pyClassName=apply-to class of the Data Page payload;
   pyScope=scope level controlling isolation and simulation eligibility;
   pyStructure=structural shape of the Data Page payload (Page or List).
S: A Rule-Declare-Pages rule defines a named, reusable clipboard page populated on demand.
   It is referenced by name in RUT expressions and dependency rule expressions.
   The Data Page is populated by a connector, activity, or data transform defined in the rule.
S: Data Pages are the primary mechanism for supplying external or reference data to rules
   under test. They are read-only from the perspective of the RUT unless explicitly
   written back by the rule.
I: pyScope is a blocking field. It must be resolved from the Data Page RuleJSON before
   any simulation eligibility decision is made.
I: Simulation eligibility is determined solely by pyScope from the Data Page RuleJSON.
   It is never inferred from rule name, apply-to class, structural shape, or usage context.
R: KDP.2, KDP.3.

KDP.2|A|ScopeEligibilityGate
P: Unified scope enumeration, isolation semantics, and simulation eligibility algorithm.
A: 1. Read pyScope from the Data Page RuleJSON.
   2. Map pyScope to isolation level, eligibility, and resolvedScope:

   pyScope="Thread"
     -> isolation: scoped to current requestor thread; isolated per test run
     -> ELIGIBLE; resolvedScope="Thread".
   pyScope="Requestor"
     -> isolation: scoped to requestor session; shared across threads
     -> INELIGIBLE; resolvedScope="Requestor".
   pyScope="Node"
     -> isolation: scoped to server node; shared across all requestors
     -> INELIGIBLE; resolvedScope="Node".
   pyScope absent, null, empty, or any other value
     -> isolation: cannot be determined; isolation cannot be guaranteed
     -> INELIGIBLE; resolvedScope="unresolved".

   3. Produce binary result: ELIGIBLE or INELIGIBLE, plus resolvedScope.
   4. All agent responses to that result are defined in the Agent Instructions.
I: Only Thread-scope Data Pages are eligible for simulation in unit tests.
   This is a hard constraint with no exceptions for any other scope value.
I: A pyScope field that is absent, null, empty, or set to any value other than "Thread"
   must be treated as INELIGIBLE. Do not default absent pyScope to Thread.
I: resolvedScope must be populated from actual RuleJSON evidence, never assumed,
   defaulted, or omitted.
I: Eligibility is binary. There is no partial simulation for ineligible Data Pages.
R: KDP.1, KDP.3.

KDP.4|A|CallerInputBinding
P: Resolve caller-to-Data-Page parameters in the confirmed RuleIQ environment.
I: Parameter declarations require exact RuleJSON field-mapping evidence. A confirmed
   empty declaration is parameterless; absent metadata or an unknown export shape
   is unresolved, never an empty declaration. No universal declaration field is assumed.
A: During dependency discovery capture declaration, access path, explicit expressions,
   matching current-Param names and symbolic producers. Do not wait for concrete values
   that scenario execution will produce. Resolve metadata independently.
A: At each executed access use the state immediately before that access: explicit
   argument first; otherwise a present same-name current Param value; otherwise an
   evidenced applicable runtime default. An unresolved explicit expression wins as
   unresolved and cannot fall back. Unknown current state cannot fall back either.
I: This implicit current-Param binding is a confirmed RuleIQ convention, not a claim
   about every Pega environment. Null and initialized empty are present values;
   absence is distinct. Optional omission needs declaration evidence. Do not coerce
   strings, numbers, Boolean values or null into one another.
A: Apply earlier executed assignments/overwrites/removals in order. Skipped producers
   supply no new value; uncertain execution makes the affected value unknown until
   replaced by an executed producer. Retain separate evidence for repeated accesses.
   Freeze each concrete map/signature during scenario execution. Equal maps may share
   a simulation decision; all associated accesses retain their own evidence.
I: Seed external RUT inputs only. Param values produced by RUT steps remain execution
   results, never invented formal RUT arguments or setup values. Caller binding is
   separate from Data-Page-to-loader pass-current-parameter-page settings.
I: Parameter refinement changes existing scenarios and their testability. It cannot
   create dependency-only scenarios or remove identified scenarios. KDP.2 remains mandatory.
X: An executed Param.pyID assignment before D_GenUT supplies a declared pyID implicitly.
   A parameterless page has an evidenced empty map; an unknown declaration does not.
R: KDP.1,KDP.2; ScenarioGroup revision 1.4 DP_DECLARATION/DP_ACCESS/DP_EXECUTION evidence.
