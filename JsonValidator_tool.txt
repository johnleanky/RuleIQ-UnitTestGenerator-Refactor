<p>Before mechanical matching in either family, check explicit final-ledger consistency. For standard scalar ASSERTs, validate explicit type/comparator/value constraints even when no physical target or block matches: value-bearing TrueFalse decisions require true/false with Is True/Is False respectively; explicit string modes Text, String, Identifier, Password, TextEncrypted, DateTime, Date and TimeOfDay cannot use Is True/Is False. An invalid final decision yields Scenario-scoped TRACE_INVALID/REJECT_SEMANTICS with its current decision ID, before any ADD_ASSERTION or other assertion repair. No-value structural comparators remain allowed and do not imply truth. ASSERT plus OMIT for the same full target, mutually exclusive explicit states, or incompatible exact-value ASSERTs for the same target require REASONING_CONTRADICTION/REJECT_SEMANTICS for the affected Scenario. Do not issue REMOVE_ASSERTION or choose a value to resolve this conflict. Compare canonical final trace values directly and order-independently; never use the candidate-only legacy quoted-string fallback between two final decisions. Only compatible explicit numeric modes on both decisions may establish numeric equivalence; never coerce an explicitly textual decision because the other decision is numeric, and make the result independent of ordering. Conflicting explicit value types require semantic rejection; When cells remain exact text. Different compatible comparator assertions are not inherently contradictory. Apply OMIT absence checks to When cells as well as standard assertions.</p>
<p></p>
<p>Build a multiset of final trace ASSERT decisions and visible RuleCode assertion items. Match kind, canonical full target, comparator and normalized value with multiplicity, not a set that hides duplicates. Require both directions. A missing explicit assertion yields ASSERT_MISSING/ADD_ASSERTION; an extra physical assertion yields ASSERT_EXTRA/REMOVE_ASSERTION. Wrong value for the same explicit target/kind is ASSERT_VALUE_MISMATCH/FIX_ASSERTION. Wrong block kind is ASSERT_BLOCK_INVALID/FIX_BLOCK_TYPE when the existing decision fixes it. Report exact affected current Scenario/decision where available. Resolve OMIT targets literally relative to the recorded primary page (or exactly as When cell paths); do not apply ASSERT duplicate-segment cleanup to OMIT. An explicit OMIT forbids a matching physical asserted target; report OMIT_ASSERTED/REMOVE_ASSERTION, not a new ASSERT.</p>
<p></p>
<p>ResultCount decisions map to block-level count comparator/value and list context; do not confuse count with exact item values. Param.* requires a Param Property assertion with full Param name/path and Text mode, without regular-page fields. For ordinary Property/List children compare pyPageName, pyPropertyApplyToClass and pyPropertyMode directly with the corresponding trace page/class/mode. Compare block pyStepPageClass with the class explicitly recorded for its step page in primary/P&amp;C context; embedded child class can legitimately differ from the enclosing step-page class. A mismatch uses DOC_ASSERTION_BLOCK_KIND_MISMATCH/FIX_BLOCK_TYPE at the affected Scenario. Ordinary properties retain the block page/class and their own page/class/relative/full-path context; do not reinterpret them as Param. Page/PageList object existence/error checks use Page blocks and allow compact children. List assertions retain InAllInstances or the recorded InAnyInstance meaning; never replace one with the other to make a mismatch pass. TrueFalse exact decisions use Is True/Is False with native true/false values; a string true/false remains text with its stated string comparator. If an explicit string-mode ASSERT has a valid string comparator but the physical value is native boolean true/false, report Scenario-scoped ASSERT_VALUE_MISMATCH/FIX_ASSERTION to restore the explicit text, even when JSON spellings match. If only the physical comparator is wrong, restore the valid explicit comparator through projection repair. Do not extend these scalar boolean/string constraints to blanket rejection of arrays/null or reconstruct hidden source types (DEC-030). Existence is not truth. No-value comparators Exists/Not exists/Is Empty/Is Not Empty/has errors/has no errors do not require an expected value; exact/string/error-message comparators require their recorded value. Do not infer values from prose.</p>
<p></p>
<p>Check directly visible EvidenceSummary counts against final ASSERT/SIM/OMIT rows and RuleCode. AssertionCount counts concrete final assertions/cells; ExactValueAssertionCount excludes structural/count and includes value-bearing non-count decisions; StructuralAssertionCount is the remainder; OmittedClaimCount and SimulatedDependencyCount count their final rows. Only compare other dependency/closure/parameter/property counters when their required evidence is actually visible. Do not recompute waves, complexity, closure or testability from missing source records. A visible count mismatch is COUNT_MISMATCH/FIX_COUNTS and is not a new semantic decision.</p>
<p></p>
<p>ReasoningTrace is not an alternate assertion source. A clearly identified candidate claim with neither final ASSERT nor OMIT yields DECISION_NOT_FINALIZED/REJECT_SEMANTICS; a narrative mention alone does not demand an assertion. Conflicting final decisions/unsupported exact support or obvious contradiction yields semantic rejection; do not guess which decision wins. Do not derive dependencies, assertion requirements, expected values, simulations or true/false coverage from RUT logic. Validator returns no rewritten trace/candidate.</p>

<p>## V7. Complete SIM identity and visible simulation behavior</p>
<p></p>
<p>Retain every canonical SIM field including sig and params. For each Scenario, associate every SIM with exactly one physical pySimulation entry by exact rule name and class; no missing/extra/collapsed/duplicate mock. SIM_MISSING/ADD_SIMULATION is only for an existing explicit SIM with missing physical mock. A physical mock with no final SIM is SIM_SHAPE_INVALID/FIX_SIMULATION. Method/type mismatches use DOC_SIMULATION_METHOD_INVALID or DOC_DATAPAGE_RULETYPE_INVALID, action FIX_SIMULATION. The physical entry must represent Rule-Declare-Pages and DefineData, with its complete visible pySetupPages. A mocked DP represented as a matching LoadDataPage setup action is DOC_DATAPAGE_IN_SETUP/MOVE_TO_PYSIMULATION; a real unrelated setup load is not automatically a mock.</p>
<p></p>
<p>DEC-016 comparison includes exact sig and normalized typed params in each trace's complete mock identity, and equality of those identities across all Scenarios sharing a When RuleCode. Two signatures mapped to one physical mock cannot be silently collapsed. Different shared When identities are a group-scoped TRACE_INVALID/REJECT_SEMANTICS. Do not substitute rule|shape|method-only matching. The current unchanged candidate schemas have no separate DP signature/parameter or payloadPage/itemPath carriers in pySimulation. Thus Validator checks the exact fields that are present and their consistent unique mock association; Generator remains responsible for proving those trace facts and hidden source bindings against ScenarioGroups. Do not compare DP params to unrelated RUT arguments, reconstruct opaque DP_SIG, require a new schema field, or claim missing source provenance was independently verified (DEC-030).</p>
<p></p>
<p>Check visible page/list mock behavior against relevant UTC descriptions. A list requires an object wrapper and its evidenced domain collection; do not force pxResults or Code-Pega-List when another wrapper/collection is evidenced. If the candidate does not expose which of several nested arrays is the source-bound collection, do not select one or reject unrelated arrays for another item class. A visible missing wrapper/collection is DOC_LIST_SIMULATION_WRAPPER_MISSING/FIX_SIMULATION; wrong visible page/list/class/depth is SIM_SHAPE_INVALID/FIX_SIMULATION. Do not invent payload data or infer RUT access paths; unsafe unresolved documentation ambiguity uses AMBIGUOUS/HUMAN_REVIEW only if it blocks safe validation. List source-binding completeness remains Generator-owned.</p>

<p></p>
<p>Keep exact namespace, leading dots, nested segments, indices/keys, case and spelling such as AccessPage.Roles(3).Permission(10).Value. Input pyDisplayLabel must equal the full path and Result label/path is Result. Input mode is text, type input; Result is last with type result and explicit string true/false. <p></p>
<p>Do not evaluate When logic or require new true/false coverage. <p>## V9. Documentation pass and invocation completion</p>
<p></p>
<p>After schema success, exact read, all-unit RUT check and usable UTC lookup, inspect only documented behavior relevant to fields present in RuleCode or required by explicit decisions: Data Page placement/method/type, page/list wrapper and class/depth, Param versus ordinary Property shape, Page/List/ResultCount blocks, comparator/value behavior, error-message formatting, primary page and Pages &amp; Classes consistency. Do not invent a Pega error-message format from an example; preserve exact error text and report only a demonstrated relevant documentation mismatch. Unavailable safe correction is HUMAN, not new semantics.</p>
<p></p>
<p>Do not manually validate required/additionalProperties, enum membership, types, oneOf/anyOf/allOf, patterns, item limits or any other candidate JSON Schema keyword. Those belong solely to JsonValidationTool. Defensive response/candidate-view checks and report serialization are separate from candidate schema revalidation. Report a documentation defect only when the observed behavior contradicts a clear applicable rule; successful checks generate no issues.</p>
<p></p>
<p>Before returning, deduplicate identical defects, use stable unit/Scenario/check traversal order, derive counts/valid/route from the entire issues array, verify allowed code/action and current coordinates, and emit only the compact report. No per-item success pages, echo of complete trace/RuleCode/Knowledge, result persistence, further tool call or retry. Short issue messages name the defect and projection-only action; bound them to 240 characters and schema summaries to 2,000 characters without hiding distinct blocking scopes.</p>
